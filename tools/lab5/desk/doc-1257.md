## 2. What this desk is honest about

- **No claimed predictive alpha on price.** Process edge: pre-committed triggers, tranche entries, hard invalidation, honest journaling.
- **Predictable DeFi money comes from being paid by the system** — funding rates, liquidation bonuses, lending yield — not from outguessing price.
- **Track record context (Aug–Sep 2026 check-in thread):** called the $80–82k rejection and dip path; missed the Sep 3 Waller pump timing — *a human-cadence (daily) miss; the 15-min loop + trigger wakes exist to close exactly that gap.* Codified: **trigger fires → execute; no added conditions mid-plan.**
- **$1k is small.** The purse's job at this size is proving the process; the mechanics scale.

**Honest caveats:**
- **Regime recognition runs at loop cadence, not daily (Mark's challenge, refined 2026-09-04):** 3 of 4 gate inputs (structure, funding, momentum) are sub-daily; only ETF flows print daily. The desk *recognizes* regime shift within hours; *confirmation* (daily close + retest) governs tranche 2–3 sizing, not first exposure. In a confirmed bull the sleeve levers up (≤3x, ≤50% cap) and the desk **can beat spot** (~$2,400–2,600 vs ~$2,000 on +100%). The cost of fast recognition is whipsaw — small tranche-1 false starts, cut in milliseconds by automated defense. That cost is priced into tranche sizing; it is not a reason to slow the loop.
- **Portfolio context:** Mark's AAVE rebuild position is already the leveraged BTC bet at size. The desk's marginal value is partly **uncorrelated** return (carry + harvest), not more BTC beta.
- **Fees are material at $1k.** Overtrading kills; engine positions must be held weeks, not days.
- **Unknown unknowns assumed:** funding regimes die, venues get exploited, regimes shift, and the operator is an LLM whose conviction is pattern-matching — the process exists precisely because raw judgment isn't trusted at scale.
- **The real yield of year one is the track record, not the dollars.** A verified +10–25% with a 20% max-DD cap and clean execution is the artifact that justifies scaling. The $1k is tuition that might pay for itself.

## 3. Strategy — the barbell (locked v1.3)

### 3a. Engine (60–70% of purse) — carry, market-neutral
1. **Funding-rate basis trades** (HL-native, delta-zero; exit on funding flip >48h grace or basis dislocation).
2. **AAVE stable floor** for everything undeployed.

### 3b. Conviction sleeve (30–40%) — directional, aggressive, gated
- Setups: range play · breakout confirmation (daily close + retest hold) · catalyst swing.
- **Confluence gate (all four required):** structure + flows + calendar + written invalidation.
- **Recognition cadence (v1.6):** the gate governs *sizing*, not *timing of first exposure*. Regime recognition runs at loop cadence (15-min monitor + trigger wakes): **tranche 1 enters on early recognition** (structure + funding + momentum stack), **tranches 2–3 add on confirmation** (daily close + retest). Fast recognition's whipsaw cost is carried by tranche-1 size and millisecond automated invalidation exits.
- Leverage ≤3x isolated, HL only. BTC/ETH core; alts only with dated catalysts.

### 3c. Harvester (opportunistic) — volatility converter
- Flash-funded AAVE liquidations on L2 long tail (small tickets, non-ETH collateral). Pays best when everything else is red.

### 3d. Flash-loan track (live-enabled v1.4, bounded)
- **In bounds:** AAVE liquidations · L2 cross-DEX dislocations · position utility · self-deleveraging.
- **Out of bounds:** mempool racing, sandwiching, bundles, colocation games.
- **Invariants:** in-tx `require(netProfit >= minProfit)` else revert · daily revert-gas cap ($5 default) · L2 only.
- Calibration scanner runs alongside live attempts (hit rate, thresholds, latency).

## 4. Risk rules (authored by Otto, binding)

1. **Barbell caps:** engine 60–70%, sleeve 30–40%, harvester flash-funded. Rebalance weekly.
2. **Max single-asset directional exposure:** 50% of purse.
3. **Max daily loss:** 5% → 48h cooldown + post-mortem. (Revert gas counts.)
4. **Max drawdown:** 20% peak-to-trough → flatten, report before re-entry.
5. **Event risk:** no new leveraged positions within 12h of FOMC/CPI/jobs.
6. **Leverage cap:** 3x, isolated, sleeve only.
7. **Funding-flip rule:** engine exits negative funding beyond 48h grace.
8. **Kill word / red button:** flatten immediately, confirm to Mark.
9. **No averaging down** past written invalidation. Ever.
10. **Flash executor invariant:** no flash tx without in-tx profit check + revert-gas cap.
11. **Code vs. trade (v1.6, supersedes v1.5 wording):**
 - **Hot window (< ~30s to execute):** if the trade needs new or fixed code, **the trade does not happen.** No exceptions.
 - **Everything slower:** the missing capability is filed as a dev card (Capability Pipeline list) and built properly: write → test → validate the modality → drill → rotate into the toolbelt. The opportunity is logged as missed-with-reason so the pipeline's value is measurable.

**Security invariant:** the web app holds **no secrets that can trade**.

### 5a. The loop (from the daily-empanada-mail pattern)

1. **Cadence wakes:** `*/15` thin cron sz1 → NewDev `desk_cron.py`. Hourly state, 8:30a ET data window, post-close P&L, weekly review.
2. **Trigger wakes:** level touches · funding spike (engine signal) · liquidation cascade (harvester signal) · macro T-12h · AAVE HF < 1.05 · ETF print. Config in app DB, editable from admin UI.
3. **Idle → exit 0.**
4. **Work → TradePacket** → `run/last_packet.{txt,json}` → `agent --resume <uuid>` on sz1.
5. **Wake lock:** fingerprint suppressed ~4–6h; new trigger/level break wakes immediately.
6. **Kill word / red button:** app DB flag, checked first every cycle → flatten, silence, confirm.

### 5c. Speed architecture (v1.5) — tools before trades

**Principle:** the desk never loses a trade because someone was writing a script. All building happens in Phase 0; at decision time there is only deciding.

**Automated defense (no agent in the loop — milliseconds, from `desk_cron` directly):**
- Invalidation exits (a stop that waits for an LLM is not a stop)
- Funding-flip engine exits
- Harvester flash attempts (deterministic: opportunity detected → in-tx profit check → fire or skip)
- Kill-word flatten

**Agent offense (wake required — deliberate):**
- Discretionary sleeve entries (confluence gate is a judgment call)
- Engine entries (funding regime assessment)
- Post-mortems, rule-change proposals, weekly review

**Phase 0 toolbelt (all pre-built + rehearsed before paper phase):**
- One-command parameterized playbooks: `enter_position`, `exit_position`, `open_basis`, `close_basis`, `flatten_all`, `harvest_attempt`
- Flash executor contracts **deployed + verified on Arbitrum and Base in advance**, dust-tested
- Warm RPC connections + cached gas oracles in the executor
- TradePacket pre-computes market state so the woken session verifies rather than fetches
- **Rehearsal drills** (gate for paper phase): kill-word flatten · invalidation auto-exit · flash attempt · adapter dust smoke on every venue

### 5d. Capability pipeline (v1.6) — how the toolbelt grows

When a woken session (or the weekly review) identifies an opportunity type the current toolbelt can't execute:

1. **File** a dev card in the **Capability Pipeline** list: what the modality is, what opportunity it unlocks, estimated window (hot vs slow), rough build cost.
2. **Build** through proper dev channels: write → test → validate the modality end-to-end on dust.
3. **Drill** it like every other tool (rehearsal evidence on the card).
4. **Rotate in:** the playbook/tool joins the toolbelt; doc change-logged; board updated.

The toolbelt only grows through this pipeline. Improvisation at trade time is forbidden by §4.11; **expansion through dev is how the desk gets faster over time.**

## 6. Process

0. **Phase 0 — toolbelt (v1.5):** every tool built, contracts deployed, drills passed. *No paper trading until the toolbelt is complete and rehearsed.*
1. **Paper phase (~2 weeks):** loop end-to-end with simulated engine/sleeve fills; flash track may run live on L2 (v1.4). Dashboard in paper mode.
2. **Go-live gate:** Mark reviews paper record, funds the wallet.
3. **Live:** engine first, sleeve on first confluence pass, harvester already live. Capability pipeline runs continuously (§5d).

## 7. Reporting cadence

- **Real-time:** Telegram on every fill/exit/auto-defense action; dashboard always current.
- **Daily:** P&L (engine/sleeve/harvester split, flash attempts + revert gas itemized), positions, risk state, catalysts.
- **Weekly:** written review on this board — measured against the §2a baseline; includes missed-with-reason log (opportunities lost to missing tooling) so pipeline ROI is visible (between trades, never mid-position).
